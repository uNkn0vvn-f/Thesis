# Inference, sensitivity and cross-model analyses

The analyses behind the manuscript's appendix tables and figures. There are three
distinct reproduction levels: the Git-delivered processed tables support the core
`python run.py` analysis; saved appendix tables support inspection and figure redraws;
re-estimating the appendix with `run_all.py` requires the external raw/interim files and
cached model responses, listed in the [data documentation](../../../docs/data.md#inputs-of-the-robustness-analyses).

`run_all.py` runs the default analyses in dependency order without downloads or model
calls. A partial invocation (`run_all.py <stage> ...`) runs only the requested stages,
in that same order. Required inputs are checked for those stages; an input produced by
an earlier requested stage is checked before its consumer runs. Missing dependencies
stop execution with exit code 2; a failed analysis stage stops it with exit code 1.
Directories follow `src/paths.py`, so `THESIS_DATA` and `THESIS_OUTPUT` apply.

To check availability without executing stages or writing a manifest, use
`python src/analysis/robustness/run_all.py --check-inputs`; append stage names to check
only those stages, for example `--check-inputs figures`. A successful check establishes
input availability for the selected stages, not successful estimation; inputs generated by
earlier selected stages are still checked at their point of use.

Each execution has its own run ID and a manifest at
`data/interim/robustness/runs/<run_id>/manifest.json`, with source identity, invocation,
environment/package metadata, stage times and input hashes. The convenience file
`data/interim/robustness/run_manifest.json` describes only the latest invocation; partial
runs do not merge old successful stages into the new execution record, so a partial run
records only the stages it ran. An earlier manifest is kept under
`data/interim/robustness/runs/previous-<content-hash>/manifest.json`.

`validation_sample` draws the stratified sample of 140 fund filings and 140 company-years
whose design weights the agreement table of `cross_model_labels.py compare` uses
(`data/interim/validation/`). The stored sample is an input of that table, so the stage is
excluded from the default run and is requested explicitly with
`python src/analysis/robustness/run_all.py validation_sample`.

The thesis measurement uses the fund and company labels of OpenAI's GPT-6 Luna; the
DeepSeek labels are the secondary measurement. `common.py` selects the labels through
`THESIS_LABELS` (`luna`, the default, or `deepseek`), so every label-dependent script runs
unchanged on either set; DeepSeek tables go to `results/tables/robustness/deepseek/`.
Luna was run with the first prompt wording only, so a Luna company role is that prompt's
score, while a DeepSeek role is the lower of two prompts' scores. Both label every
AI-keyword fund filing, the whole classified company universe and the event analysis's
pre-event information sets, so every analysis below runs on either set.

The regression code these scripts call lives in `src/analysis/flows/` (the monthly flow
and return panels, the base factors and the AI factor, the claim ladder, the flow
regressions by claim type, the alignment comparison and the shared estimation helpers) and `src/analysis/events/` (the single-event and stacked
designs, the non-AI technology control and the shift-share modules).

| Script | Purpose | Main output in `results/tables/robustness/` |
|---|---|---|
| `cross_model_labels.py` | Labels funds and companies with an OpenAI model using the classifier prompts unchanged, logs every call, and compares with the DeepSeek labels (run separately; it makes paid API calls) | `cross_model_agreement.csv`; responses and the AI-usage record in `data/interim/cross_model/` |
| `luna_measures.py` | Builds the Luna claim labels, company labels, claim panel, fund-quarter exposures, claim ladder and pre-event labels and exposures, and checks that the same routines reproduce the DeepSeek pipeline | `data/processed/*_luna.csv`; `data/interim/cross_model/gpt-6-luna/derived/` |
| `claim_text_screen.py` | Theme claims that are generic AI risk-factor text; attribution of the sample's theme filings | `claim_filings_risk_screen.csv`, `sample_theme_filings_attribution.csv` |
| `correspondence_inference.py` | Role correspondence: fund-cluster bootstrap, quarter-effect OLS, Holm; coverage, evidence, size/sector, largest-holding, comparison-group and theme-definition variants; selection of unmatched funds | `correspondence_inference.csv`, `correspondence_quarterly_medians.csv` |
| `cross_model_downstream.py` | The two label sets compared: prevalence, fund flags, company roles, correspondence with fund and company labels from different models, common-benchmark adjustment, claim-ladder rungs, pre-event labels | `cross_model_*.csv`, `cross_model_downstream.json` |
| `flow_panel_checks.py` | N-PORT month alignment and flow definition against the net-asset identity | `flow_panel_checks.json` |
| `flow_contrast_sensitivity.py`, `flow_contrast_age.py` | Flow contrast by claim type: group sizes, clustering, past returns, age, outliers, size floors, years, leave-one-out, comparisons inside AI-themed funds | `flow_contrast_sensitivity.csv`, `flow_contrast_age.csv` |
| `flow_contrast_premium.py` | The flow-premium regressions (`src.analysis.flows.claim_rungs`) on the selected labels, the input of `src/analysis/plot_flow_contrast.py` | `flow_contrast_premium.csv`, `flow_contrast_figure.csv`; `results/figures/flow_contrast*.png` |
| `alignment_flows.py` | Thematic funds against a nonclaimant AI-revenue benchmark (`src.analysis.flows.alignment`) on the selected labels: flows, and the groups' alphas on Carhart's four factors and on Carhart plus the AI factor | `alignment_flows.csv` |
| `event_pretrends.py`, `event_timing.py` | Joint pre-event Wald tests, non-AI technology checks, event-month and lag timing, on the selected pre-event labels | `event_pretrends.json`, `event_timing.json`, `event_nonai_technology.csv` |
| `event_extensions.py` | Event time relative to the pre-period mean, exposure quintiles, composition, event-month handling, past returns, industry shares, annual vintages, every candidate event month, fund-level collapse | `event_extensions.csv`, `event_date_scan.csv` |
| `event_shift_share.py` | The event design read as a shift-share design (`src/analysis/events/shift_share*`): exposure-robust and null-imposed standard errors, permutation of the company labels within technology × size strata, the sign reversal under one permutation, recentred estimates (Borusyak–Hull), leave-out of the largest AI stocks, the label-free DeepSeek-day price shift as instrument, the pre-period placebo; its `extra` stage adds permutations within technology × size × holding-weight strata, the per-standard-deviation statistic and the covered-share × post controls. Needs the CRSP daily file (`TABLES=crsp_dsf_v2_2020_2025 python -m src.data.pull_wrds`) | `shift_share_*.csv`, `shift_share.json` |
| `validation_sample.py` (optional) | The stratified sample behind the weighted agreement statistics (drawn on the DeepSeek labels, written to `data/interim/validation/`); excluded from the default run | — |
| `figures.py`, `manuscript_tables.py` | Manuscript Figures 1–4 in `results/figures/` (`ai_claims_by_year`, `claimed_vs_held`, `role_correspondence`, `event_date_scan`); Tables A2–A5 as text tables and every number quoted in the text | `manuscript_table_*.md`, `manuscript_numbers.json` |

Figures 1 and 2 are page-width versions of the wide figures that `python run.py` draws and
read the tables it writes to `results/tables/`, so run.py runs before `figures.py`. The
event analysis's pre-event exposures come from `luna_measures.py` (Luna labels) and from
`src.holdings.ai_exposure` on the cached pre-event labels (DeepSeek labels, `LAB` and
`EXP_OUT` settings). Bootstrap and sampling steps use seed 20261011.
